Python Backend Setup Commands: Scratch to Production

For your Python backend learning, use uv as the primary Python project and dependency manager, FastAPI for APIs, SQLAlchemy + Alembic for database access and migrations, PostgreSQL for persistence, and Docker for deployment.

The table below compares Python pip, Python uv, and Node.js npm commands. They are comparable workflows, but not every command has an exact equivalent.

Important distinction: uv add updates the project's dependency declarations and lockfile. uv pip install is closer to pip and installs into an environment without managing the project dependencies in the same way. For a new uv project, prefer uv add and uv sync.

For the Uvicorn command, app.main:app means the app/main.py module and the app variable inside that module. Your file should contain app = FastAPI().

Development commands enable convenient reload behavior. Production commands should run without development reload.

Before generating migrations, configure Alembic to load your SQLAlchemy model metadata. Otherwise, autogeneration may not detect your tables. Review every generated migration before applying it.

4. My recommended command sequence

For a fresh FastAPI + PostgreSQL backend, run these in order:

# 1. Install Python and initialize the project
uv python install 3.12
uv init product-api --bare
cd product-api
uv python pin 3.12

# 2. Install application dependencies
uv add "fastapi[standard]" sqlalchemy alembic "psycopg[binary]" pydantic-settings

# 3. Install development dependencies
uv add --dev pytest httpx ruff pytest-cov

# 4. Create and synchronize the environment
uv lock
uv sync

# 5. Initialize migrations after configuring SQLAlchemy metadata
uv run alembic init alembic

# 6. Run development server
uv run fastapi dev app/main.py

# 7. Quality checks
uv run ruff check .
uv run ruff format --check .
uv run pytest

# 8. Production dependency synchronization
uv sync --locked --no-dev

The migration initialization step assumes you have created the app package and configured your Alembic settings before generating and applying database migrations.

Recommended rule: use uv add when changing dependencies, uv sync to synchronize the environment, uv run to execute project commands, uv.lock to reproduce dependency versions, and uv sync --locked --no-dev for a production-oriented dependency installation.
